# AGENTS.md

## Commands (run from repo root)

- Full test suite (no torch, GPU, or engine packages needed — verified on a bare dev box):
  `python -m pytest tts-engine-common/tests/ impl/tests/ tools/tests/`
- Single test: plain pytest, e.g. `python -m pytest impl/tests/test_server_omnivoice.py -k seed`
- After changing a server's request schema or engine constants, regenerate snapshots and review the diff:
  `python impl/tests/update_snapshots.py`
- `tts-engine-common` does **not** need to be installed for tests — its conftest (and `impl/tests/_bootstrap.py`) add `src/` to `sys.path`.
- No lint, typecheck, formatter, lockfile, CI, or pre-commit is configured. Don't go looking for it or invent one.
- Actually running a server requires the engine package + a GPU and downloads model weights from HuggingFace on first start. The test suite never does this.

## Layout

- `tts-engine-common/` — shared FastAPI + Pydantic package. Design constraint: **no torch, no engine deps** — it must stay importable and testable on any box (see `pyproject.toml` comment and `docs/01-server-generification.md` D7).
- `impl/` — ten standalone FastAPI server scripts, one per engine: `server_breezeBlue.py`, `server_chatterbox.py`, `server_omnivoice.py`, `server_qwen3TTS.py`, `server_qwen3TTS_mlx.py`, `server_fasterQwen3TTS.py`, `server_dotsTTS.py`, `server_indexTTS.py`, `server_luxTTS.py`, `server_voxcpm.py`. Run via `python impl/server_<name>.py` or uvicorn; env config is documented in each module's docstring.
- `impl/tests/` — GPU-free test suite + committed `/capabilities` snapshots (`snapshots/`).
- `tools/` — `speak.py`, a command-line testing tool for any engine server: stdlib-only (no torch, no engine deps, no need to install `tts-engine-common`), discovers engine parameters from `GET /capabilities`. GPU-free tests in `tools/tests/` (network and aplay stubbed). Spec: `docs/03-speak-script.md`.
- `docs/` — design docs; `01-server-generification.md` contains the binding decisions (D1–D7).

## Architecture facts that change how you work

- The Pydantic `SynthesisRequest` model is the single source of truth: `GET /capabilities` is **derived** from it at import time via `build_capabilities()` (decision D4). Change the model, then regenerate the snapshot — never hand-edit the capabilities doc or a snapshot to match.
- Request models use `extra="forbid"` deliberately (D5): unknown fields must fail loudly with 422. Don't "fix" that into `extra="ignore"`.
- Servers read env config at **import time** (module-level `os.getenv`). Tests pin env in `impl/tests/_bootstrap.py` *before* any server import — that file is shared by `conftest.py` and `update_snapshots.py`, so keep the pinned values in sync with the servers' documented defaults.
- Core request vocabulary: `text`, `audio_base64`, `reference_text`, `language`, `seed` (`CORE_FIELDS`). Core response: `audio_base64`, `sample_rate`, `seed`, `time_used`, `rtf` plus per-server extras (e.g. `fid`). `language` is *not* guaranteed core — check `/capabilities`.
- The `language` contract (docs/02-language-handling.md): **two-letter lowercase codes** only; null/empty normalizes to `en` at the request boundary (shared helpers in `tts_engine_common.language` — reuse them, don't re-implement). Engines with a different internal format (Qwen3-TTS lowercase names, dots.tts uppercase codes) map codes at their own server; auto-detection is exposed as the special value `auto`. This is why `schema_version` is 2 — don't "fix" servers back to accepting names/free-form.
- Three distinct output rates: 24 kHz (Chatterbox, OmniVoice, Qwen3-TTS, Qwen3-TTS MLX, faster-qwen3-tts, Breeze TTS 2), **48 kHz** (dots.tts, LuxTTS), 22.05 kHz (IndexTTS). dots.tts auto-selects CUDA/CPU (no device env var); its snapshot's `device` field is machine-dependent and the test deliberately compares everything *except* `device`. LuxTTS does take a `LUX_TTS_DEVICE` env var and reports the *configured* device in capabilities (pinned in `_bootstrap.py`), so its snapshot's `device` is deterministic. Don't "fix" a device mismatch in either case.

## Test gotchas

- `impl/tests/stubs/` provides import-only stand-ins for `torch`, `numpy`, `soundfile`, `loguru`, and each engine package. Stubs are appended to `sys.path` **last**, so real installed packages always win on a GPU box.
- The stub `numpy` must satisfy pytest's own introspection (`isscalar`, `bool_`, `ndarray`, `asarray`). If a cross-suite run dies with `AttributeError: module 'numpy' has no attribute ...`, see the comment in `stubs/numpy/__init__.py`.
- Pydantic v2 lax mode coerces `"yes"`/`"true"`/`"1"` to booleans — boolean-rejection tests must use values that are *not* coercible.
- `impl/tests/test_language_contract.py` asserts the shared docs/02 language contract once across *all* servers (null/empty → `en`, 422 for garbage/uppercase/names/non-strings, `auto` per declaration, capabilities default). A new server must be added to its `SERVERS` list; per-server suites keep only engine-specific language tests.
- The suite covers the HTTP surface (capabilities, health, validation, 400/422 pre-flight, and — for Qwen3-TTS MLX and Breeze TTS 2 — the no-audio-output 500 path (stubbed empty generator). Actual synthesis is **not** tested (it needs a real model + GPU); the `/synthesize` success path is exercised where a test installs a fake model: faster-qwen3-tts (`impl/tests/test_server_fasterQwen3TTS.py`) pins argument forwarding to `generate_voice_clone`, and Breeze TTS 2 (`impl/tests/test_server_breezeBlue.py`) pins the request dict, template selection, guidance kwargs, and seed/request-id forwarding to the streaming runtime.

## Per-engine quirks

- **Chatterbox** — no `reference_text` field (deliberate; it conditions on audio only). Only the first 10 s of the reference are used. Output is PerTh-watermarked by the library.
- **OmniVoice** — omitting `reference_text` triggers on-the-fly Whisper transcription; the first such request pays the ASR model load. References over 20 s are trimmed at the largest silence gap.
- **Qwen3-TTS** — `language` takes two-letter codes (`en`, `zh`) or `auto`; the server maps codes to the engine's lowercase *names* internally (`en` → `english`). Omitting `reference_text` transparently enables speaker-embedding-only mode.
- **faster-qwen3-tts** — CUDA-only fork of Qwen3-TTS (`FASTER_QWEN3TTS_DEVICE` must start with `cuda`; the engine has no CPU/MPS backend). `xvec_only` (default `true` — deliberately out of step with the engine's ICL library default; our testing found x-vector the more consistent voice for streaming, don't "fix" it back) is x-vector mode: `reference_text` is ignored and the voice is consistent across requests (the sentence-streaming mode); `xvec_only=false` is ICL mode, where `reference_text` is **required** (422 without it — do not add an automatic x-vector fallback) and the voice can vary between requests (fresh random seed per request by default). `language` takes two-letter codes or `auto`; the server maps codes to the engine's lowercase *names*. The engine caches the encoded voice prompt per (file path, transcript), so the temp prompt file is content-hashed (SHA-256) rather than UUID-named **and kept on disk** — per-request deletion would race with a concurrent request for the same clip still queued on the synthesis lock (staging happens before the lock is taken); wipe the staging directory to reclaim space. Synthesis is serialized with a lock: the engine replays captured CUDA graphs (static buffers, not re-entrant) and keeps a shared prompt cache.
- **Qwen3-TTS MLX** — Apple-Silicon/MLX backend using `mlx-audio`. ICL voice cloning only: `reference_text` is **required** (422 without it — do not add an implicit speaker-embedding fallback at the server boundary). `language` takes two-letter codes or `auto`; the server maps codes to the engine's lowercase names internally. `seed` is meaningful and is applied with `mx.random.seed()` before generation
- **dots.tts** — the runtime demands a file path for prompt audio, so the server writes a temp file; reference transcript is optional. `language` takes two-letter codes or `auto`; the server maps them to the engine's uppercase codes / `auto_detect` internally.
- **IndexTTS-2.5** — 22.05 kHz output. No `reference_text` field (conditions on audio alone; first 15 s hard cut). Reference clips are staged as content-hashed (SHA-256) temp files that are **kept** — the model caches conditioning per path; wipe the staging dir to reclaim space. Emotion via at most one of `emotion_audio_base64` / `emotion_vector` (8 components) / `emotion_text` (needs `INDEXTTS_USE_QWEN_EMO=1`). `language` restricted to the five advertised codes (anything else 422s); no `auto`. `seed` is best-effort (no engine seed parameter).
- **LuxTTS** — 48 kHz output. Imports as **`zipvoice`** (stub dir `stubs/zipvoice/`; the package is a git repo, not on PyPI). No `reference_text` field (deliberate; the engine *always* transcribes the reference with Whisper — openai/whisper-base on GPU, whisper-tiny on CPU — so every request pays the ASR cost; the ASR model loads once at startup). No `language` forwarding: the engine has no language parameter (tokenizer auto-detects en/zh per segment, other scripts dropped), so the server accepts any two-letter code but does not forward it, and capabilities advertise `languages: null` — the no-support case of docs/02. `seed` is meaningful (solver initial noise from the PyTorch RNG; seed via `seed_everything` inside the synthesis lock) — reproducibility is bit-exact on CPU and near-exact (~1e-7 differences) on CUDA because of non-deterministic GPU kernels; don't "fix" the docstrings to claim bit-exact GPU output. The runtime demands a file path for prompt audio; the reference is one-shot (no engine prompt cache), so the temp file is deleted per request. Synthesis is serialized with a lock: `generate_speech()` mutates the shared vocoder's `return_48k` flag in place. `t_shift` must be > 0 (the solver's timestep schedule degenerates at 0).
- **VoxCPM** — 48 kHz output (with dots.tts and LuxTTS). 2B-parameter tokenizer-free TTS with three modes: **voice design** (no reference audio; the voice is described in parentheses at the start of `text`), **controllable cloning** (reference audio only), and **ultimate cloning** (reference audio + `reference_text`; the server passes the clip as both prompt and reference audio, so the model treats the clip as a spoken prefix and continues from it). `reference_audio` is *optional* (unlike most engines — voice design needs no clip); `reference_text` **requires** `audio_base64` (a cross-field validator 422s without it — a transcript with no clip is a client error, not a mode switch; don't "fix" it into a silent voice-design fallback). Cloning needs a VoxCPM2 checkpoint: the engine rejects `reference_wav_path` on VoxCPM1 models, and VoxCPM1 outputs 16 kHz — the response `sample_rate` is read from the loaded model (`model.tts_model.sample_rate`), not a constant, so a 1.x checkpoint via `VOXCPM_MODEL` at least self-corrects in the response (the capabilities doc is derived at import time and still says 48000). No `language` forwarding: the engine has no language parameter (auto-detects from text, 30 languages), so the server accepts any well-formed two-letter code but does not forward it, and capabilities advertise `languages: null`. `seed` is meaningful: `seed_everything()` plus the engine's own `torch.manual_seed` inside the synthesis lock; the response echoes the engine's `last_successful_seed` (read under the same lock), not the requested seed — `retry_badcase` (default on) increments the seed across retries, so echoing the request's seed would be a lie; bit-exact on CPU, near-exact on CUDA. The ZipEnhancer denoiser is deliberately *not* exposed (`load_denoiser=False` is hard-coded — no env var, no request field; a parameter that can never work is worse than none). `VOXCPM_DEVICE` accepts the engine's full grammar (`auto`, `cpu`, `mps`, `cuda`, `cuda:<index>`): the import-time check validates the grammar, the engine checks availability at load; `VOXCPM_MPS_DTYPE` is import-time-validated to fail fast. The runtime demands a file path for reference audio, so the server writes a UUID-named temp file, deleted per request (one-shot engine, no path-keyed cache). Synthesis is serialized with a lock: KV caches are mutated in place, `torch.compile`d functions are not re-entrant, and `@torch.inference_mode()` contexts are thread-affine.
- **Breeze TTS 2** — CUDA-only (the streaming runtime hard-rejects non-CUDA devices; `BREEZEBLUE_DEVICE` must start with `cuda`). The engine is a plain git repo (no packaging), so the server imports its `breeze_infer`/`models` packages only when the repo root is on `PYTHONPATH` — run `PYTHONPATH=. python ../tts-serve/impl/server_breezeBlue.py` from the repo root; the server's guarded import converts the missing-package case into an actionable startup message. The checkpoint must be a *local directory*: the engine downloads the backbone/text tokenizer from HuggingFace but reads the bundled `audio_tokenizer/` subdirectory from disk, so `BREEZEBLUE_MODEL` should point at a `huggingface-cli download BreezeBlue/breeze-tts-2 --local-dir ...` result. Voice clone and voice direction only — the engine's voice-design mode is deliberately *not* exposed (client does not support it), so `audio_base64` **and** `reference_text` (the exact transcript) are both required; omitting either is a 422, not a mode switch. An optional `instruction` switches to voice direction (same speaker, steered delivery) and is stripped before the engine call; `cfg_scale` (default 1.0, README recommends 4) is the CFG strength (finite and > 0 — `+inf` is rejected by a validator, mirroring the engine CLI); a non-default value **requires** `instruction` (422 without it — the CFG branch only exists on the voice-direction template, so the engine would 500 the combination otherwise; don't "fix" it back into a silent clone-mode default). No `language` forwarding: the engine auto-detects English/Chinese from text, so capabilities advertise `languages: null` (docs/02 no-support case). `seed` is meaningful: the process RNG is re-seeded per request and the engine re-seeds PyTorch at the start of sampling; near-exact on CUDA (non-deterministic kernels), so don't promise bit-exact GPU output. The runtime demands a file path for reference audio and re-encodes each request (no path-keyed cache), so the temp file is deleted per request. Synthesis is serialized with a lock: the streaming runtime mutates shared KV/codec state in place and the engine's own API is single-request behind a lock. `BREEZEBLUE_FAST_ALL=1` enables the CUDA-graph fast path (one-time warmup from the engine repo's `configs/fast.json`, located relative to the `models` package; import-time check fails fast if it's missing; ~14.4 GiB vs ~7.7 GiB eager).

## Adding a new engine

Copy the existing pattern: `impl/server_<name>.py` (config + deps in the module docstring, `extra="forbid"` request model, capabilities derived at import) + `impl/tests/test_server_<name>.py` + a snapshot generated by `update_snapshots.py`. See `impl/README.md` for the current parameter table and `docs/00-project-overview.md` Goal 3 for the intended workflow. In OpenCode, the `new-tts-engine` skill (`.agents/skills/new-tts-engine/SKILL.md`, registered via `opencode.json` `skills.paths`) walks through the full workflow including the test stub.
